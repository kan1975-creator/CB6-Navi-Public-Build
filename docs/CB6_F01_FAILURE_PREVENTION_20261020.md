# CB6-F01 失敗記録・再発防止基準

記録日: 2026-10-20
状態: ユーザーが失敗項目として指定。再発防止基準案を記録。GitHub正式登録・Registry変更は未実施。

## 失敗
同一の残存FAILについて、全体原因の整理と既存資料の活用が不足したまま個別是正・独立レビュー・承認工程を繰り返し、完成に結び付かない作業を増やした。過去の承認原文が見つからないことと、既存コードから技術的な現状を読み取れることを混同した。

## 原因
1. 目先のFAILへの局所対応を優先し、34項目・39経路・DDL全構造の共通原因を先に整理しなかった。
2. GitHubの現行設計書・契約・ソースを使った根拠整理が遅れた。
3. STOPの適用範囲を過度に広く解釈し、読み取り専用の技術確認と正式承認の証明を混同した。
4. 次工程の価値（新証拠・新差分・解消見込み）を検証せず承認操作を求めた。

## 再発防止の必須チェック
- 次工程前に「前回からの新しい証拠・差分」「解消対象」「完了判定」を明示する。
- 新証拠・差分がない同一調査・レビュー・試験を提案しない。
- 同じFAILが続く場合、個別是正を止め、共通原因と一括是正の範囲を先に整理する。
- 実装の技術的証拠、現行仕様、過去の本人承認を混同しない。
- 未確認をPASSにしない。部分改善を完成扱いしない。
- ユーザーに求める操作は、誰が・何を・なぜ・どのように・完了条件を平易に示す。
- 本人承認のないコード変更、試験、SHA再計算、DB生成、GitHub書込、Actions、APK、Releaseを行わない。
- R228/R233正式採用、R243③④限定PASS、R225/R227/R232既存PASS、全STOPを維持する。

## 再発検出
同じFAILについて新証拠・新差分・明確な解消見込みがないのに、再度の調査・レビュー・承認工程を提案した場合はCB6-F01再発としてSTOPし、理由を報告する。
